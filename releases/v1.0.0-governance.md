# Release Notes: M.A.R.C.U.S. v1.0.0-governance

**Milestone:** `1.0.0-governance.1`  
**Directive:** `MARCUS-DIR-001`  
**Status:** Prepared on the `docs/marcus-dir-001-operating-directive` branch; not a published GitHub Release.  
**Scope:** Governance records and structural schemas in the M.A.R.C.U.S. Meta Engine repository.

## Summary

This milestone records the project-level operating directive and establishes machine-readable directive and subsystem registers. It supports the operating cycle:

`BUILD → OBSERVE → ANALYZE → EXPERIMENT → TEST → LEARN → IMPROVE → CONTINUE`

The records explicitly distinguish directive adoption from subsystem connection, capability, execution, and runtime activation.

## Included

- `docs/MARCUS_DIRECTIVE_001.md` — project-level directive adoption record.
- `config/directive-registry.json` — machine-readable directive record.
- `config/subsystem-activation-register.json` — nine subsystem entries, each with a verification status and evidence ledger.
- `schemas/marcus.subsystem-activation-register.v1.schema.json` — structural validation for status and evidence metadata, including SHA-256 digest syntax and JCS evidence requirements for `VERIFIED` entries.
- `schemas/hermes.semantic-envelope.v1.schema.json` — initial H.E.R.M.E.S. semantic-envelope structural contract.

## Evidence and integrity notes

A digest string is metadata until a verifier recomputes it against the precisely defined evidence bytes. The schemas do not implement RFC 8785 canonicalization or SHA-256 verification. A `jcs_canonicalized` value of `true` is an assertion that consumers must independently validate. Current subsystem entries are `PENDING_TEST` and have no evidence records; no test result is implied.

The 432 Hz and 20-TET fields are represented as requested project mapping conventions. Their presence does not establish that incoming physical observations are calibrated, nor does structural validation establish scientific or musical validity.

## Runtime status

External subsystem runtime activation remains unconfirmed. No live subsystem, UDP/OSC route, REAPER control surface, or telemetry engine was activated or tested in this milestone. The proposed Python and C++ harness examples require implementation review and executable verification before they can be treated as validated project tooling.

## Verification status

This milestone adds schema and documentation artifacts only. Automated schema validation and harness execution have not been performed in this repository-writing operation.
